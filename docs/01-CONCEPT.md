# Концепция продукта: Raznaia TMS

> Рабочее название системы автоматизации транспортной логистики (аналог TransTrade).

## Проблема

Транспортные компании и экспедиторы ведут заказы в Excel, мессенджерах и разрозненных программах. Это приводит к ошибкам в ставках, потере документов, просрочкам оплат и невозможности быстро оценить рентабельность перевозки.

## Решение

**Raznaia TMS** — веб-система для управления грузоперевозками: от поступления заказа до печати заявки и контроля оплаты.

## Целевая аудитория

| Роль | Задачи в системе |
|------|------------------|
| Логист / диспетчер | Создание заказов, подбор перевозчика, контроль статусов |
| Менеджер | Работа с клиентами, коммерческие условия |
| Бухгалтер | Счета, акты, контроль задолженности |
| Администратор | Пользователи, права, настройки |
| Водитель *(v2)* | Мобильный кабинет, статус рейса |

## MVP — что входит в v1.0

| Входит | Не входит (v2+) |
|--------|-----------------|
| Справочник клиентов | Интеграция с 1С |
| Справочник перевозчиков и ТС | ЭДО / ЭТрН |
| Создание и редактирование заказа | SMS-уведомления |
| Статусы заказа | Мультифирма |
| Расчёт ставки (фикс / км) | Мобильное приложение |
| Печать заявки (PDF) | Маршрутизация Maxoptra |
| Базовые отчёты (список заказов, фильтры) | АТИ |
| 1 пользователь (admin) | RBAC на несколько ролей |

## Конкуренты

- **TransTrade** — desktop, богатый функционал, модули, 18+ лет на рынке
- **1С:Управление автотранспортом** — для компаний на 1С
- **Облачные TMS** (Logistics OS, Kibana и др.) — SaaS-модель

**Наше отличие на старте:** простой веб-интерфейс, быстрый старт без установки, открытый код для обучения и доработки.

## Модель монетизации *(перспектива)*

- Бессрочная лицензия по числу рабочих мест (как TransTrade)
- Или SaaS-подписка для облачной версии
- Дополнительные модули докупаются отдельно

## Бизнес-процесс «Заказ → Оплата»

```mermaid
flowchart LR
    A[Заявка клиента] --> B[Создание заказа]
    B --> C[Подбор перевозчика]
    C --> D[Назначение ТС]
    D --> E[Перевозка]
    E --> F[Документы]
    F --> G[Оплата клиента]
    G --> H[Оплата перевозчику]
```

## Статусы заказа (MVP)

```
draft → confirmed → assigned → in_transit → completed → closed
                  ↘ cancelled
```

| Статус | Описание |
|--------|----------|
| `draft` | Черновик, данные неполные |
| `confirmed` | Заказ подтверждён с клиентом |
| `assigned` | Назначен перевозчик и ТС |
| `in_transit` | Груз в пути |
| `completed` | Доставка выполнена |
| `closed` | Документы и расчёты закрыты |
| `cancelled` | Отменён |

## Критерий успеха MVP

Логист может за одну сессию: создать заказ → назначить перевозчика → сменить статус → скачать PDF-заявку.
